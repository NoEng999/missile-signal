# 北朝鮮ミサイル → Signal（Windows試運転版）

## GitHubからのインストール

このリポジトリをダウンロード・展開し、Python 3.11以降をインストールしたWindowsで、まず Setup.cmd を実行してください。依存ライブラリ・Signal CLI・ポータブルJavaを取得します。続けて Start.cmd で起動し、SignalをQR連携します。設定例は config.example.json にあります。認証情報・実行環境・運用ログはリポジトリに含めていません。

現在の運用対象は防衛省・NHKのWeb/RSSです。Xは既存コードを保持していますが、APIキーが空欄の場合は無効です。GitHub Actionsはテスト専用で、24時間の監視はWindows PCで実行します。

## 起動と受信確認

1. `Start.cmd` をダブルクリック。Web監視は自動で開始します。
2. 「SignalをQR連携」を押します。スマートフォンのSignalで「設定 → リンク済みデバイス → デバイスを追加」を開き、画面に出るQRを読み取ります。既存のスマートフォンのアカウントをリンクします。
3. 連携完了後、「模擬発射をSignalへ送信」を押し、スマートフォンの「メモ」に速報と詳細が到着することを確認します。模擬情報には必ずテストと表示します。
4. スマートフォンで通知音・ロック画面通知まで確認します。自分のメモの通知挙動によっては、別の送信元Signalアカウントと受信先番号を使う必要があります。送信成功表示だけでは端末への到着を保証しません。

ウィンドウを閉じると監視と、このソフトが起動したSignal送信プロセスを停止します。電源停止・スリープ中は監視できません。自動起動やWindowsの電源設定変更はまだ行っていません。

## 通知の順序

## グループチャットへの通知

アプリを閉じて `Start.cmd` で再起動すると、更新したグループ選択画面が使えます。Signalの再連携は不要です。

1. スマートフォン側で通知先グループに参加していることを確認します。管理者だけが投稿できるグループの場合、送信アカウントに投稿権限が必要です。
2. 「グループ一覧を取得」を押し、「通知先グループ」で対象を選びます。
3. 「通知先の種類」が「グループ」になっていることを確認して「設定を保存」を押します。保存後の通知は選択したグループに送信します。
4. 「模擬発射をSignalへ送信」でグループ内の受信を確認します。グループにテスト通知が送られるので、必要に応じて参加者に事前に知らせてください。

グループ名の後の短い識別子は、同名グループを区別するためのものです。グループの招待リンクを貼る必要はありません。一覧にない場合は、連携端末への同期を待って再取得してください。

送信先を保存すると、保留中の未送信通知にも新しい送信先が適用されます。切り替え前に古い保留通知を送りたくない場合は「未送信キューを消去」を押してください。アプリは対象グループを自動で選択せず、ここまでの更新作業でグループへのメッセージ送信は行っていません。

## 通知処理

新着・更新を検知したら、他の情報源との照合や詳細取得を待たず、発射報道／発射の可能性を通知キューに入れます。詳細より速報を優先送信します。発表日時が取れない場合は未取得のまま、検知日時と元のリンクを付けます。推定や可能性という情報源の表現は残します。

詳細通知では弾数、EEZ・領海、弾着予想を含む原文の一部を抽出します。内外を推測で補いません。EEZと領海は別の概念で、EEZ外から領海外などを推論しません。未発表・抽出できない項目はその旨を表示します。長い記事・PDFの原文抽出は試運転段階であり、リンク先での確認が必要です。

情報源をまたぐ重複は許容します。同一情報源の同一内容の無限再送は抑止します。初回の取得成功時は既存記事を登録するだけで、過去のニュースを速報として送りません。監視を停止していた間の記事を自動で遡る機能はありません。

未連携・送信失敗時には通知をSQLiteに保存し、再試行します。検知から2分以上経過した通知は「遅延送信」と表示します。「未送信キューを消去」で不要な保留通知を消せます。送信タイムアウトでは相手に届いたか判定できないため、重複送信が起こり得ます。

## 情報源と取得間隔

- 防衛省: https://www.mod.go.jp/j/surround/northKorea/index.html 。発表リンクの新着と、直近3ページの内容更新を監視。
- NHK RSS: https://www3.nhk.or.jp/rss/news/cat0.xml
- NHK Web: https://news.web.nhk/newsweb 。記事見出しの新着を監視し、関連する記事は本文を後から取得。
- X: 防衛省 `@ModJapan_jp`、NHKニュース `@nhk_news` のミサイル関連投稿。公式Filtered Streamに常時接続。

Web取得の初期値は10秒。設定可能な最小値は5秒です。取得・処理に時間がかかった場合にはその分延びます。Webサイト自体の更新頻度やRSSの配信時刻も影響するため、発射からの遅延や通知の取りこぼしゼロは保証できません。発射の自動判定は日本語表現のルールによるもので、未知の表現や記事構造の変更への対応は運用で確認します。

接続失敗は情報源ごとに画面表示し、他の監視を継続します。Signalの詳細ログは `data/signal-daemon.log`、監視ログは `data/monitor.log` に保存します。

## Xを有効にする

X Developer Consoleで利用可能なBearer Tokenを取得し、画面のX欄に入力して「設定を保存」。アプリを閉じて起動し直します。APIキーはチャットに貼り付ける必要はありません。

X APIには従量料金がかかるため、利用者がDeveloper Consoleで契約・クレジット・上限を設定してください。このソフトは課金契約を作成しません。キーが空欄ならX監視は停止したままです。起動時に専用タグ `missile-signal-local-v1` の取得ルールを追加します。他のアプリのルールは削除しません。Xの接続数制限により、他のストリーム利用と競合する場合があります。

## GitHubと移行

ソース、README、requirements.txt、テストをGitHubに保存できます。`.gitignore` で設定・APIキー・Signal連携データ・ログ・実行環境を除外します。`data/` と `config.json` には機密情報が含まれるのでアップロードしないでください。

このPC用の起動はGUIですが、監視処理 `Engine` はGUIから分離しています。将来VPSへ移行する際は常駐プロセス用の起動処理とSignalの再連携を追加します。GitHub Actionsの定期実行は通知速度を優先する常駐監視の実行環境には適しません。

## 実行環境・検証

実行に必要なのはPython 3.11以降、signal-cli 0.14.9、ポータブルJava 25です。Pythonをインストールして `Setup.cmd` を実行します。signal-cliは非公式ツールであり、Signal側の変更に合わせて更新が必要です。SignalやXの認証情報は配布物に含めていません。

`runtime\Scripts\python.exe test_monitor.py` : 過去記事抑制、情報源ごとの重複、可能性と予定の判定、詳細抽出、速報の優先送信、ローカル模擬Signal HTTP送信を確認。

`runtime\Scripts\python.exe monitor.py --check` : Webの実接続とパーサーを確認。初期履歴を登録します。
